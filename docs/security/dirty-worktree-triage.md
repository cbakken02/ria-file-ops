## Risks

- Auth/OAuth risk: wrapping NextAuth and adding app-level rate limits can break sign-in, callbacks, CSRF/session metadata, or provider redirects if the route handler context is wrong. Verify before commit.
- Production-risk caveat: the in-memory limiter is per-process/per-instance and not durable. It should not be represented as full production abuse protection; Vercel Firewall or a shared store remains needed before broader demos/users.
- Documentation drift: the audit docs must keep `docs/security/risk-register.md` and `docs/security/security-roadmap.md` as the canonical current status for PROD-001, while preserving historical pre-fix findings.
- Dependency risk: the Next.js patch bump is unrelated to the other dirty changes and can change build/runtime behavior. Keep it separate.
- Logging risk: the safe logging helper reduces exposure, but future logging can still leak data if raw objects are added elsewhere. Add regression tests if this becomes a formal logging-control risk.
- Sensitive-data scan: a metadata-only scan of dirty files found environment variable names and documentation references, but no URL-shaped database values, known token prefixes, private-key blocks, or obvious raw secret values. No actual `.env` values were printed or inspected.
